# Firestore Security Rules — подписка

Вставить в Firebase Console → Firestore Database → Rules, заменив текущее
содержимое (или добавив эти два `match`-блока в существующие правила).

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Подписка — читать может только сам пользователь. Писать может любой
    // залогиненный клиент (у нас нет сервера), но только с ограниченными,
    // проверяемыми правилами полей — не даёт просто написать
    // { status: 'active', subscriptionEndDate: <cколь угодно далеко> }.
    match /subscriptions/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;

      allow create, update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.status in ['active', 'trial', 'expired']
        && request.resource.data.subscriptionEndDate is number
        // не больше 31 дня от текущего момента — не даёт выписать себе
        // подписку на 100 лет вперёд
        && request.resource.data.subscriptionEndDate
             <= request.time.toMillis() + 31 * 24 * 60 * 60 * 1000
        && request.resource.data.lastPaymentHash is string
        && request.resource.data.lastPaymentHash.size() == 66;
    }

    // Использованные txHash — реестр "этот платёж уже засчитан". Создать
    // можно один раз (кто первый — того и подписка), перезаписать или
    // удалить нельзя никогда. Это и есть защита от повторного использования
    // одного и того же платежа на разных аккаунтах или для продления.
    match /usedPaymentHashes/{claimId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null
        && request.resource.data.uid == request.auth.uid;
      allow update, delete: if false;
    }
  }
}
```

## Честно про пределы этой защиты

Это закрывает:
- ✅ Правку статуса подписки напрямую через `localStorage` (был полностью
  открытый способ, теперь бесполезен — источник правды в Firestore).
- ✅ Повторное использование ОДНОГО реального платежа для продления без
  повторной оплаты.
- ✅ Использование ОДНОГО реального платежа сразу на нескольких аккаунтах.
- ✅ Проверку, что подтверждённая транзакция — это реально перевод USDC на
  наш адрес на нужную сумму (не любая успешная транзакция, как было раньше).

НЕ закрывает полностью (нужен настоящий бэкенд, чтобы закрыть до конца):
- Технически подкованный человек может обратиться к Firestore SDK напрямую
  из консоли браузера и попытаться записать документ с **выдуманным**, но
  формально подходящим по длине `txHash` (0x + 64 символа), который никогда
  не существовал в блокчейне. Правила Firestore не могут сходить в RPC и
  проверить, что хэш реальный — это может сделать только сервер.

Если захочешь закрыть и это — понадобится Cloud Function (или отдельная
serverless-функция на Vercel), которая сама проверяет транзакцию в
блокчейне и только после этого пишет в Firestore от имени админ-SDK, а
клиенту вообще запретить прямую запись в `subscriptions`. Это отдельная,
не очень большая, но реальная задача с бэкендом — раньше мы такой бэкенд
специально убрали из проекта (упрощали архитектуру), так что тут выбор
между "проще, но не 100% пуленепробиваемо" (текущий вариант) и "чуть
сложнее, зато полностью надёжно".
